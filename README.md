# 周策 · 广告经营复盘

每周上传 DeepBI Excel 报告，结合历史数据复盘全店营业额与实际 ACOS，检查逐品异常、查看有证据的目标调整候选，再记录人工实际执行结果。

这是单用户应用：FastAPI + SQLite + 原生 HTML/CSS/JavaScript。开发启动默认仅监听本机，不直接操作 Amazon 或 DeepBI。公网部署使用密码登录、HTTPS 和持久化存储，部署配置见 [DEPLOY.md](DEPLOY.md)。

工作台支持亚马逊阿联酋站点（AE / AED）和沙特站点（SA / SAR），顶部可切换站点及中文 / English。报告、历史比较、执行记录和经营目标分别按站点展示与保存，不合并两种币种的金额。首次升级时，阿联酋沿用原有经营设置，沙特默认实际 ACOS 目标为24%；之后可分别修改。

语言选择会记住，并用于登录页、工作台、规则说明和分析导出。切换语言只改变展示，不重新分析或改写历史快照；商品名称、文件名、人工备注及已生成的 AI 自由文本保留原文。英文界面会说明 AI 内容使用原生成语言。

## 启动

```bash
cd /workspace/gaunggaoxitong
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

在可访问该运行机器的浏览器中打开本机8000端口。云端环境需要产品支持的访问入口；本项目没有自动发布公网网站。

停止进程后，原始报告、分析快照和确认记录仍保存在 `data/`。下次启动使用同一个目录即可恢复，进程本身不需要保持存活。

## DeepSeek 配置

通过服务器的安全环境设置注入 `DEEPSEEK_API_KEY`。不要将真实密钥写进 Git、报告、聊天或前端代码。

可选环境变量：

| 名称 | 默认值 | 用途 |
|---|---|---|
| `DEEPSEEK_MODEL` | `deepseek-chat` | 模型 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | HTTPS接口基础地址 |
| `WEEKLY_DATA_DIR` | 本项目的`data/` | 持久化目录 |
| `WEEKLY_ACCESS_PASSWORD` | 未设置 | 服务器安全环境中设置至少16字符的登录密码 |
| `WEEKLY_REQUIRE_AUTH` | 开发模式未开启 | 公网部署设为`1`，缺少登录密码时拒绝启动 |
| `WEEKLY_COOKIE_SECURE` | `true` | 登录Cookie仅通过HTTPS传输；只在本机HTTP测试时可设为`false` |

没有密钥时仍可使用上传、规则分析、历史与执行确认，页面会明确显示“AI未连接”，不会把规则分析冒充 DeepSeek 输出。配置密钥并重启后，可以在历史报告中重新分析，保留旧版本并生成新的AI复核结果。

配置登录密码后，报告、分析、备份和文档接口均需登录，只有健康检查无需登录。登录有效期12小时；修改服务器中的登录密码并重启，会让旧登录失效。分析设置页可退出登录。网站登录密码与DeepSeek API密钥相互独立，不应复用。

分析分两阶段：

1. 程序对全部Listing核算指标、识别数据问题和保护条件，生成可追溯的候选动作。
2. DeepSeek复核最多80款优先对象、历史概况和最近执行记录，解释证据和待排查原因。覆盖范围在限制说明中展示；全量产品仍有规则分析。AI不会直接覆盖程序已验证的目标数值。

DeepSeek调用是后台任务；失败不会删除原文件或规则结果。AI服务不可用时显示失败原因，重新分析会创建新快照。重启时未完成的AI任务会标为中断，可手动重试。

## 每周流程

1. 每周一导出前一完整7天的报告，上传时核对站点、开始和结束日期。文件名有日期时会尝试填入，但以用户确认的字段为准。
2. 查看总览：实际加权ACOS、广告销售、原报营业额及其可靠性、零广告成交消耗、库存保护和数据质量。
3. 查看逐品建议和证据，区分立即可执行的受控试调、观察候选、异常排查和库存保护。
4. 在DeepBI自行完成调整。回到本产品填写实际目标、实际执行时间和备注，确认后留下审计记录。
5. 下周上传新报告，系统对照相同站点、相同周期的历史与实际执行记录，防止频繁反复调参。

确认只是记录你的陈述，不证明广告平台已执行。下一份报告的目标字段若与确认不一致，系统会提示核实。与建议不同的值、或没有自动建议的人工调整，必须填写备注。每份报告的每个ASIN只能确认一次，确认后不能通过重新分析重复记录；再次调整应在后续报告中留档。

## 经营与分析规则

- 默认实际ACOS参考目标24%，同时争取全店营业额增长，增长且ACOS下降为更优结果。
- 单品输入目标是调控参数，不要求机械统一成24%；高目标但实际达标的产品不会被一律收紧。
- 逐品ACOS数值提示色按该品输入目标判断，与全店经营预期分开；缺少实际在投流量数据时，不将提示色冒充DeepBI完整的流量颜色分类。
- 当前账户库存规则：库存严格小于3，不扩张探索，预算强制为1。等于3不触发这条规则。预算1的具体层级和金额口径以实际账户为准。
- 零广告销售时ACOS不可计算，不能将导出的0%当优质表现。
- 7天和30天报告不直接比较金额增长；重叠周期、不同站点也不用于周环比。间隔存在缺口时有明确说明，不能据此直接生成调参动作。
- 当前目标、库存、日预算是快照，不代表整期一直如此；种子数不等于点击、曝光或当前在投数量。
- 只有连续可比历史、足够订单、可靠数据、无近期变更等证据才给可执行的目标试调。当前实现可提出有证据的收紧试验；没有曝光/点击/预算受限证据时，提高目标只会列为增长观察方向，不伪造精确扩量建议。
- 两期各至少5单、超目标至少10%、执行后至少14天观察等，是本原型可审计的保守决策条件，不是DeepBI的内部算法，也不保证最优结果。
- 异常原因列为可能原因及排查步骤，不能仅凭汇总报告证明是产品差、算法故障或某次调整造成。
- 总销售、广告销售、自然销售无法核对时，不给出可靠的营业额增长结论。广告归因销售增长不等于全店新增销售。

初次只有一份30天报告时，可能没有任何可执行目标调整。这是证据限制的正常结果；异常与排查建议仍会完整展示。项目当前已导入用户此前提供的413款真实30天报告作为历史基线，没有把合成测试数据混入实际工作台。

## 保存与备份

`data/weekly.sqlite3`保存报告行数据、每次分析的完整结果与设置快照、用户实际执行记录；`data/uploads/`保存原始Excel。分析使用SHA-256加站点和日期范围去重。旧分析不会被后来的重分析覆盖；未完成的同一次AI复核仅更新它自己的AI结果。

设置页可下载完整备份ZIP，包含数据库和所有原始文件，不包含API密钥。恢复时先停止服务，将ZIP中的 `weekly.sqlite3` 与 `uploads/` 放入持久化目录，再启动。备份应保存在独立位置；只有本机持久化不等同异地备份。正式部署请把该目录映射到持久化磁盘并安排定期备份。

交付的源码ZIP不含用户数据；在另一台机器使用此前的真实报告时，请另行恢复“真实报告与分析备份”ZIP。云环境的安装脚本、启动说明与DeepSeek密钥要求已保存为配置草稿，需要在环境设置中保存并发布后生效；真实密钥仍需通过安全环境设置填写。
